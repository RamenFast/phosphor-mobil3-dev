# Decision record: 2026-07-25 Phosphor 2.0 release contracts

**Status:** Ratified and binding
**Implementation in this phase:** Contracts and custody verification only
**Release version:** `2.0.0`

## Context

The approved release materially changes distribution, package identity, signing, first-party control, state ownership, privileged experimentation, public publication, and rollback. It is therefore Phosphor 2.0 rather than a 1.x feature update.

Phase 00 preserved the exact private, public, Nexus, artifact, signer, S25, installed-package, Shizuku, Concourse, build, and test baseline at commit `70c8e2860bfe22310dd41bb341b19202580fef56`. The dated Nexus consultation was recovered, sealed, and checked against current source.

## Decisions

1. **Release identity:** The release target is `2.0.0`.
2. **Packages:** Play is `dev.phosphor.mobil3`. Fortress is `dev.phosphor.mobil3.fortress`.
3. **Fortress signer:** Fortress uses the healthy Ben-controlled RamenFast estate certificate SHA-256 `e4d14ce2d62983acd393f012cbce759b6c97bdcca979feeb04a97afb279d9b00`.
4. **Play signer:** Installed Play builds use a separate Google Play App Signing identity. Its certificate is recorded after Console enrollment.
5. **Debug preservation:** The installed debug `dev.phosphor.mobil3` remains untouched while Fortress is installed and validated. A later Play migration requires signed export, archived APK identity, explicit debug uninstall, Play install, and import.
6. **Release signing:** Every release build fails closed for absent, wrong, or incomplete signing inputs. Debug-key fallback is forbidden.
7. **Nexus signer activation:** The currently installed debug-signed Nexus is development-only. Production same-phone Binder authority requires backup/export, uninstall, estate-signed reinstall, import, signer verification, negative trust tests, and rollback rehearsal. Inner enrollment cannot bypass Android's signature permission.
8. **Two reach paths:** The existing desktop seven-verb Nexus host adapter and the full mobile Binder/authenticated-tailnet protocol are strict projections of one causal store, action grammar, revision order, provenance stamp, refusal grammar, and audit log.
9. **Seven-verb compatibility:** The host adapter remains exactly `status`, `play`, `pause`, `xy`, `waveform`, `snapshot`, and `schema`, with no generic passthrough. Internal liveness probing is not an eighth public control verb.
10. **Same-phone transport:** Fortress exposes a real bound Binder/AIDL service protected first by a manifest `signature` permission, then by package, current certificate, accepted signing lineage, build profile, protocol version, token/enrollment, and independently revocable capabilities. Localhost/TCP is forbidden.
11. **Remote transport:** Phosphor dials outward to the watched tailnet gate. Tailscale membership is not sufficient authentication. The application session also uses a pinned endpoint and nonce-bound, revocable authorization.
12. **Causal semantics:** Every mutating UI or agent action uses expected revision, idempotency key, requested capability, and one provenance/receipt identity. Duplicate identical requests replay the original acknowledgement. Conflicting key reuse, stale revision, revocation, or lost authority refuses before effects.
13. **Liveness:** Explicit revoke/disconnect and Binder death stop authority immediately. HUD decay is bounded by one negotiated heartbeat for explicit closure. Unexpected remote loss closes after the declared missed-heartbeat lease.
14. **CLI:** Exits are `0` success, `2` unavailable, `3` bad input, `4` runtime failure. One-shots have a non-empty RFC 3339 timestamp and `data`; streams have canonical `event`; device operations require an explicit serial.
15. **Audio truth:** UI, renderer, Nexus, CLI, HUD, persistence, and receipts share the canonical source states defined in `spec/AUDIO-CONNECTIVITY-AND-PROJECTM.md`. Protected, opted-out, silent, connected-without-signal, and unavailable states are never collapsed into `flowing`.
16. **Rollback:** Phase reverts, retained tags/releases, suffix-only Fortress uninstall, archived APK reinstall where needed, and signed settings/theme import form one release rollback manifest.

## Consequences

- Flavor separation and signing validation precede privileged implementation.
- Shared schemas and reducers precede active Binder/tailnet transports.
- Fortress capability is not weakened to fit Play.
- Current debug Nexus cannot be described as production same-phone authority.
- Play Console, legal, banking, tester, and final master/main promotion gates remain human-controlled.
- A failed privileged-audio experiment is an acceptable truthful result when its matrix, limits, fallback, and rollback are complete.
