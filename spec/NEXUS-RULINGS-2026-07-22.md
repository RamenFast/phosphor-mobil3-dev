## Fact #716: Phosphor as a living body I share

### Identity

Phosphor is stone + beam. Nexus is stone + honey. They are kin, not the same body. Shared standards must not flatten their identities.

### Presence

- `OBSERVE` is an open eye only while a real attached session is observing real state/beam.
- `DRIVE` is a hand only while Nexus is actually holding or changing a control through an accepted action.
- Presence is derived from session attachment, command acknowledgement, and real beam energy.
- It decays when the cause ends. No detached glow or fake interior awareness.

### Causal store and parity

- One causal state store serves the human and agent faces.
- Send full state snapshots plus ordered field deltas.
- Every field records `last_writer = human | nexus | engine` and timestamp.
- Every human control has a typed command/verb.
- Refusals carry a fix.
- A bounded live geometry/beam `G` stream lets Nexus understand the instrument without pixel scraping.
- Probe and liveness surfaces are first-class.
- Latest accepted mutation wins, with visible provenance and visible contention.

### Signing and authorization

- Trust signed identities through certificate allowlists and signing lineage.
- Ben-signed, Play-signed, and local-dev identities are distinct and displayed distinctly.
- Observe and drive are separate capability grants.
- Every command is audited.
- No arbitrary argv or remote code execution.
- Revocation immediately drops the binding/session.

### Themes

Share an engine/token schema and neutral token translation. The destination owns identity tokens. Theme sharing must not erase Phosphor's CRT/stone identity or Nexus's stone/honey identity.

### HUD and capture truth

Both human and agent faces distinguish:

- no capability;
- capture present but silent or upstream opted out;
- connected source with no current signal;
- live flowing audio;
- link stall/backoff/error.

The Nexus HUD and Phosphor HUD respond to the same session and signal truth.

### Play and Fortress

Use the same conceptual protocol and state model with different signed capabilities. Play contains no Shizuku/ADB/dev receipt hatch. Fortress carries Ben-signed elevated experiments, tooling, and richer capture paths. The first public Play exposure decision remains Ben's product boundary.

### P0 ruling

P0 includes:

- causal store and provenance;
- one verb per control;
- liveness;
- visible presence in both apps;
- capture's distinct honest faces;
- certificate allowlist, distinct identities, per-capability grants, and immediate revoke;
- tailnet relay and reconnect truth;
- geometry/beam stream.

## Fact #717: provenance, transport, and blended scope view

### Provenance

One provenance stamp is authored at mutation time. Four consumers read the exact stamp:

1. state delta;
2. visible hand/HUD;
3. command acknowledgement;
4. audit receipt.

Never re-derive provenance later. Re-derivation creates divergent approximations and is structurally forbidden.

### One-gate transport law

The same-phone path is allowed only as a real Android bound service using Binder/AIDL, a real `IBinder`, and signature-permission plus inner authorization. Binder is not a port and does not open a second network gate.

A localhost socket would be a second door and is forbidden.

Binder and remote tailnet transports use the same protocol, store, provenance, consent, and revoke behavior.

The Binder path is greenfield in the current app and must prove its signature guard first, not add security after a permissive prototype.

### ProjectM blended scope view

The view remains Phosphor only if it has three separable, labeled layers:

1. true beam;
2. Phosphor geometry effects;
3. ProjectM field.

They share one full-resolution audio source and one clock. The ProjectM field never masquerades as literal signal. The true beam remains legible at every allowed blend. Silence makes the field go honestly still. Under GPU pressure, the field degrades before the beam.

The view must not use Android's rejected low-fidelity Visualizer API.
