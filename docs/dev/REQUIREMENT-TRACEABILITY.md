# Phosphor 2.0 requirement traceability

**Status:** Active release matrix
**Source authority:** Ben's latest instruction, `vision/`, `spec/`, ratified decisions, Nexus consultation, workspace governance, and dated device evidence

A row may advance from `PENDING` only when every applicable evidence column names a passing receipt. `UNSUPPORTED` and `BLOCKED` are acceptable only with dated evidence, an honest product state, and a fix or fallback. `N/A` must explain why that evidence class cannot apply.

## Evidence columns

- **Implementation:** owning symbols or paths. `planned:` means the binding source exists but compilation has not reached that phase.
- **Automated check:** unit, contract, instrumentation, Rust, relay, lint, or benchmark check.
- **Artifact check:** manifest, dependency graph, archive, certificate, checksum, or public-source inspection.
- **Device observation:** physical S25 or host/tailnet evidence when behavior depends on real hardware.
- **Prohibited scan:** explicit check for forbidden fallback, leakage, unsupported claim, listener, Python, or policy compromise.
- **Receipt:** durable result path.
- **Rollback:** exact phase boundary. The commit SHA is filled when the phase commits.
