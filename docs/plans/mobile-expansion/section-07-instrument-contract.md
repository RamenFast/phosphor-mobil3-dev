# Section 7: instrument preset contract

This is the implementation contract for approved R16, authored before preset runtime code. It builds on the typed six-color contract in section06, whose integration and acceptance are still separate gates. It does not accept the unfinished root, HOLD, or Android behavior work. Canonical section7 and R15 remain unchanged.

## Source seams and scope

At mobile0591, MainActivity owns tuning persistence and local manual gain, ScopeUiState owns most authored controls, and PhosphorScreen incorrectly keeps focus in a separate remembered value while MainActivity keeps focusPref. Presets need one authored focus value with unchanged0.3 default, not a third copy. Rust render commands already serialize local tuning. Add one validated preset command rather than emitting a succession of setters. Section06's whole LightSettings is embedded without a second color clock or RNG. Remote geometry is generated by another owner and cannot participate in a local atomic transaction.

INSTRUMENT PRESETS is a named setup surface adjacent to LIGHT/Beam & Light, with a compact recall action. It is not an Appearance preset, a source selector, or a whole-app settings import. Opening, browsing, saving, importing, renaming or deleting never applies a setup. Only APPLY and UNDO apply tuning.

## Exact typed setup, version1

Use a dedicated InstrumentSetup value, not an arbitrary preference map. Every field below is required in a version1 record. Reject nonfinite numbers, wrong scalar types, unknown fields and unsupported versions before mutation.

| Fields | Accepted values |
|---|---|
| mode | Integer0..10 in the existing ModeLabels/Mode enum order |
| random_mode_armed, random_ban_modes | Boolean and unique sorted integers0..10, leaving at least two eligible modes when armed |
| geom_fx, geom_amount | Integer0..4 and finite Float0..1 |
| gain, auto_gain | Authored local manual gain0.1..7 and local auto-gain choice. Do not save a breathing measured gain or mirrored remote auto-gain as local authority |
| focus | Finite Float0.3..3 |
| beam_energy, glow | Finite Float1..30 and0..0.98 |
| beam_random_armed, beam_random_min, beam_random_max | Boolean and ordered finite range within1..30 |
| glow_random_armed, glow_random_min, glow_random_max | Boolean and ordered finite range within0..0.98 |
| grid, grid_data | Booleans for graticule and its raw-channel readout |
| oversample | Integer1,2 or4, explicitly DSP reconstruction rather than negotiated input rate |
| light | Entire section06 LightSettings: preset0..8, saved RGB bank0..6, exact membership mask, seconds, TIMER/TRACK, generated-auto, shuffle, random interval and ordered min/max |

Names, record IDs and collection version belong to record metadata, not native tuning. Scope camera gestures, view rotation and transient inspection are excluded in version1 and labeled as outside the saved setup. Also exclude FPS/presentation policy, source/transport, mic routing/mix, audio/device volume, permission or root material, startup, relay identities, appearance, HDR, screen brightness, HUD ownership and pause mode. Presets cannot reset these by omission.

The local setup is the authored tuple, not current pixels. A manual generated roll and runtime cycle/RNG/track state are not serialized. Save/create during a temporary roll records the underlying saved light setup and explains this. Do not replace saved records when ordinary controls change.

## Coherent application and cancellation

1. Parse and validate the entire candidate and its light tuple. Run the existing whole-snapshot rapid-cycle guard. A rapid candidate remains pending until the explicit acknowledgement, with safe timing active as specified by section06. The preset is not marked fully recalled if the guard produced a different safe setup. Display that difference rather than silently claiming an exact match.
2. If remote geometry currently owns the scope, reject complete application with a precise reason: the desktop owns shape/gain and a complete local preset cannot be applied atomically there. Offer the existing source controls without changing streams, sending a burst of remote setters, or claiming the desktop changed. Saving the authored local setup remains possible and is labeled local. Audio-only relay remains a local renderer path.
3. Submit one immutable validated command to the render owner. It updates local mode, clears any obsolete mode-flip request, updates related gain/geometry/beam values and installs the whole light state before another live frame observes the setup. It does not invalidate History, clear audio or visual ingress, alter a pinned image, change inspection, or reconfigure a Surface. No GPU call or device wait belongs inside its short CPU transaction. Plain renderer configuration assignments are not a pixel-acceptance claim.
4. Use a host-testable request state with pending/committed/cancelled outcomes. Waiting occurs off the main thread with a finite deadline. Timeout/cancellation before admission makes a late queued command inert. A lost reply after committed admission is resolved from that exact request result, not guessed from a timeout and then retried. Disconnected renderer, superseded request, changed source capability and destroyed caller do not publish stale success to a replacement Activity.
5. The UI shows pending then the exact committed setup, or the unchanged prior setup and a concrete error. Update only the enumerated tuning keys and the actual controls, including focus. A rejected renderer request leaves saved tuning unchanged. Treat persistence failure separately, preserve the prior snapshot, and do not claim durable success. Serialize preset application with manual tuning edits/import within the existing owner so a stale import cannot overwrite a later edit. Source stop and safety controls remain usable while an apply is pending.
6. Retain one prior InstrumentSetup for immediate UNDO after a successful apply. UNDO uses the same validation, capability, guard and transaction path. Repeated apply replaces this one undo slot. Runtime undo is not a persisted usage history. An unrelated tuning edit marks the recalled record modified without overwriting it.

HOLD keeps the existing pixels and inspection. The surface states that a committed preset is ready for LIVE. A changed preset does not manufacture a transport transition or resume display/audio. Existing section05 submission/freshness limitations remain recorded rather than hidden by preset tests.

## Records and portable documents

Store a bounded versioned collection in a dedicated `phosphor.instrument.presets` SharedPreferences file using one serialized collection value. The existing sharedpref backup allowlist already permits user settings there, while runtime/root/private endpoint exclusions stay unchanged. No new backup exception is needed. Preserve stored records through app update and failed reads. Do not overwrite an invalid collection with an empty one on startup.

Maximum64 user records and1MiB encoded document. Record IDs are generated canonical UUIDs. Names are trimmed,1..64 Unicode code points, no control characters. Names are unique case-insensitively using locale-independent comparison. A duplicate action proposes a distinct name and requires the user's save action. Rename/delete operate on stable IDs, not list indices. Deleting a recalled record leaves current tuning unchanged and clears only its association.

Use the existing Storage Access Framework document flow for a clearly titled **Instrument presets** import/export document, schema `phosphor.instrument-presets/1`. Do not silently add presets to the whole-app archive format or serialize all SharedPreferences. Include only version, typed records, names/IDs and a canonical content SHA256. Canonicalization and checksum must be tested with deterministic fixtures. No runtime identities, source files, timestamps of listening, endpoints or authorization material enter it.

Decode and validate the entire document before offering an inert import preview. Duplicate ID/name conflicts require an explicit choice to keep existing, replace the identified record, or import with a new unique name/ID. Cancel changes nothing. A malformed record or failed persistence leaves the existing collection byte-identical. Import does not apply, acknowledge rapid cycling or reset tuning. Export all user records or an explicitly selected record. Curated entries are bundled constants, not silently persisted user records.

## Curated starting set

These are visual starting points, not numerical calibration. All omit saved colors except Ambient, disable random mode/energy/glow/generated/shuffle/random interval, use focus0.3, gain1.8332275 with auto-gain enabled, geom_fx0/amount0.6, oversample1, grid_data off, TIMER3 seconds, and the existing inactive random ranges beam6..20/glow0.30..0.90. Curated setup data must pass the same validator as user records.

- **Clean XY:** mode0 (XY scope art), P7 Green preset0, beam8, glow0.20, grid on. Purpose: clear left/right geometry with short trails.
- **Spectral bench:** mode8 (Spectrum), Ice Blue preset2, beam6, glow0.15, grid on. Purpose: separate spectral motion from long phosphor trails. No calibrated amplitude/frequency claim.
- **Ambient:** mode7 (Ring), P7 Green fallback0, beam6, glow0.70, grid off. Two saved colors `[0.42,1,0.55]` and `[0.35,0.75,1]`, both selected, TIMER10 seconds. Purpose: restrained slow color interpolation and longer visual persistence, not a new audio effect.

Starting set is never auto-applied on install, import or navigation. Users may duplicate a curated entry into their own named record. There is no delete/update operation on bundled constants.

## Observable checks and handoff

- Pure setup tests cover every field boundary, finite/type checks, full six-color round trips, selection/range consistency, exclusion attempts, local/manual versus remote/measured gain, and all curated tuples.
- Collection tests cover create/update/duplicate/rename/delete, stable IDs,64-record/1MiB/name bounds, Unicode and duplicate conflicts, malformed/checksum/schema input, inert import, failed-save preservation and update survival.
- Production transaction fixtures hold admission behind a barrier, cancel or change capability/owner, and release it. No late apply or false success is allowed. Test whole-snapshot observation, rejected native state, lost acknowledgement after commit, persistence failure, rapid guard and undo. Textual JNI assertions are supplementary, not substitutes for these primitives or the Android build.
- Preserve legacy source/transport/appearance/archive behavior. A preset apply must not call root/capture/mic/relay startup, audio volume, source switching, display pause, History invalidation, or Surface configuration.
- Build both APKs with unit/lint/engine/native checks from released immutable source. Independent Astra section-level review follows with the existing four-round limit.
- On the exact installed APK, perform every CRUD/apply/undo/import flow, modified-state indication, actual six-color light guard, local and audio-only relay continuity, rejected geometry-owned apply, held-image stability and large-font/48dp accessibility. Preserve source playback position and device volume. No source-only score substitutes for this device acceptance.
