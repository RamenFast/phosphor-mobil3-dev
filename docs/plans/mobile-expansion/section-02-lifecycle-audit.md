## 3. Smallest integration obligations, with worked high-risk transitions

1. **Keep one narrow capture authority spanning both concrete services.** It must identify backend, owner, status sequence and pending retirement. It must dispatch starts/stops to the correct class. No runtime administration interface is needed.
   - Sequence: standard A flows → explicit root selection B → retire A and await recorder/projection cleanup plus service destruction → start RootCaptureService B → accept B READY/PCM → attach mirror B. A's late callback must neither clear B's mirror nor deactivate B's ring.
   - Reverse: root B flows → explicit standard choice C → supervisor/helper cleanup and reap acknowledged → launch/use fresh projection consent for C through the standard service. If B cleanup is uncertain, C never arms the ring.
2. **Reuse source-release and selection fencing before arming root.** Authorization is not source ownership.
   - Sequence: local L plays → user selects root → root authorization is pending → user selects local M → root authorization returns → discard the retired root continuation. M keeps its sample-locked audible deck and truthful metadata.
   - Sequence: relay R streams → root selection → releaseReaders acknowledges existing capture/mic → disconnect owned relay → close native deck boundary → revision reply → root start. A delayed R reconnect cannot reclaim the root ring.
3. **Preserve mic's request-specific two-part handshake.** Publish a fresh matching idle snapshot even when no capture existed, without clearing an unrelated native ring.
   - Sequence: root A → mic request M with sequence S → root STOP carries M → stop/reap + source release complete → matching IDLE sequence greater than S and release revision arrive in either order → mic starts once. M is superseded by local N before either result → no mic start. A stale M result cannot clear N.
4. **Keep stopped-owner truth through failed or superseded local requests.** Invalid input and failed cleanup are different.
   - Sequence: root A → unreadable file B → validation fails before release → A remains live. Separately: valid B reaches root STOP → B is superseded by invalid C → A actually stops → publish capture-reader loss despite B being stale → C must not resurrect A's face.
5. **Fence every asynchronous plane, not just Kotlin status.** Helper frame generation, PCM production, native activation/deactivation, metadata owner and art/controller generations all matter.
   - Sequence: root A stops → B starts after acknowledged retirement → inject A's delayed READY, PCM, failure, metadata-stop and ring-off completion → all are rejected with B's samples/face intact. A check before a blocking read is insufficient if a push can occur after ownership changes.
6. **Preserve service versus presentation ownership.** Root survives Activity/PlaybackService recreation when its actual service survives.
   - Sequence: root A flows → destroy/recreate Activity, not process → same A service/helper remains → status and MediaSession rebind → no dialog or second helper. Then recreate only PlaybackService → same A restored via owner ID. Rotation/PiP alone does not cover this sequence.
7. **Preserve the task/linger policy, including repeated removals.** Do not call default MediaSessionService task removal when it could pause unrelated external playback.
   - Sequence: linger ON, root A → remove task T1 → A and mirror remain, old T1 callbacks retired → reopen T2 → delayed T1 callback cannot stop A → linger OFF → remove T2 → stop/reap A, mirror and wake disappear. Failed reader cleanup remains a blocking retirement even when task removal destroys its Android service.
8. **Keep capture transport distinct from capture stop.** A play/pause request is not helper lifecycle control.
   - Sequence: root A mirrors controlled external player X → notification pause → only X receives pause → observed X callback drives UI truth while root may capture silence → UI LIVE off → retire A and clear mirror without sending pause/stop to X. Metadata access loss similarly removes the face, not PCM.
9. **Make root failure explicit and bounded without silent standard fallback.** Failed authorization, helper EOF, malformed/old frame, stream stall, stop uncertainty and successful stop are different outcomes.
   - Sequence: start root A → helper dies before READY → error with retry/explicit standard choice, no live claim → bounded cleanup proof → retry B may start. If teardown cannot be proven, B is refused. Killing only the ordinary parent tests supervisor ownership, not Android force-stop behavior.

This is an existing handler inconsistency, not an observed device failure or a claim that normal UI currently sends it. Smallest correction for the writer to consider: retire the unused action handler, or require a validated owner identity. Do not reuse it for root.

- `ReaderStop.finish` bounds only `reader.join`, not the preceding `stop` or following `release/cleanup` calls (`ReaderStop.kt:20,30–35`). No hang was observed. Root cannot infer an end-to-end supervisor deadline from this utility alone.
- The native capture seam is untagged. Existing Kotlin paths rely on acknowledged exclusion and reader identity. This is not independent proof of an existing stale-write failure, but adding asynchronous private PCM increases the risk substantially.
- `MainActivity.kt:394` says passive reopen is once per process, but `lastSourceReopened` at line 123 belongs to each Activity instance. Existing `onStart` restores actual capture status before `onResume`. Do not treat that comment or `consent_seen` as an authorization guarantee.
- The plan/spec illustrative root label says 48 kHz stereo (`MOBILE-EXPANSION-PLAN.md:181`, `spec/EXPANSION.md:121`), while the normative root format contract is 16 kHz mono PCM16 (`spec/EXPANSION.md:69`).
