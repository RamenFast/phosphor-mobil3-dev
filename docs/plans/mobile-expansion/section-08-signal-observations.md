### Callback and owner freshness races to preserve explicitly

1. **Old capture cleanup with no current service:** `publishStatus` rejects a different non-null owner but permits publication when global owner is null (`K/CaptureService.kt:460-464`). Its new sequence alone cannot establish current source. Tag service ID and source revision, including terminal outcomes.
2. **Mic request generation is not recorder generation:** cancelStart advances it without necessarily retiring the recorder. Existing failure fence deliberately uses recorder identity (`K/MicController.kt:100-113,126`). Route and meter callbacks need the recorder-lifetime ID.
3. **Positive read racing stop/replacement:** the read loop rechecks running and retains the epoch taken before blocking (`K/CaptureReadFence.kt:12-16`). Retain that fence and reject old-owner publication. A diagnostic getter must not resurrect a cleaned-up owner or rewrite the new source face.
4. **Root callback ordering:** sample callback occurs before frames/lastPcmAt fields update (`K/RootCaptureSession.kt:118-121`). Reading its separate volatile fields is not a coherent event snapshot. Root READY/idle/sample messages are posted to main and checked against session/owner (`K/CaptureService.kt:320-364`). Publish a single tagged aggregate after its fields are finalized.
5. **Root epoch transition:** wrong-epoch PCM can be received and counted but not normalized/admitted (`K/RootEpoch.kt:51-57`, `K/RootCaptureSession.kt:117-120`). Explain this as distinct ingress versus visual admission, not fabricated reader failure.
6. **External controller callbacks:** use existing `captureBinding.bind` identity fence and capture owner token (`K/PlaybackService.kt:474-506,1468-1469`). Old PAUSED callbacks cannot pause a replacement's diagnostic story.
7. **Relay session readout:** media status verifies session identity, but global counters and slots are separately read (`N/remote.rs:761-831`). Receive checks cancellation after blocking, then touches global state (`1406-1416`). A diagnostic snapshot must validate its session across capture/publication rather than assume all fields share one instant.
8. **Destructive peak-window read and HOLD:** a second scopeStats caller can consume the current peak. HOLD can leave it absent or briefly stale (`N/engine.rs:105-109`, `N/render.rs:590-646`). Neither condition is measured silence.
9. **Synthetic output zeros:** remote callback zeros may come from mute or underrun while valid incoming media continues (`N/remote.rs:437-478`). Incoming and finalized-output timestamps/counters need separate fields.
